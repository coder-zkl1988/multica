智能体是 [Multica 工作区](/workspaces)中的协作者。你可以把任务分配给它、在评论中 @它，或直接和它对话。它会通过绑定的运行时调用 AI 编程工具，并把进度和结果写回工作区。

智能体不会一直在后台运行。它保存的是一套可以反复使用的身份和配置，收到工作时才产生具体的[运行](/tasks)。

## 智能体的配置项

| 配置 | 作用 |
|---|---|
| **名称、头像和描述** | 让团队知道它是谁、适合做什么。描述只用于展示，不会进入执行提示。 |
| **指令** | 规定它的职责、工作方式、边界和交付要求。每次执行都会使用。 |
| **对话开场建议** | 提供最多三条针对该智能体的示例，出现在别人与该智能体开始新对话时。选择后只会填入输入框，不会发送。 |
| **Skills** | 提供可以复用的方法、参考资料和支持文件。 |
| **运行时、模型和思考强度** | 决定在哪个运行时、用哪款 AI 编程工具和哪个模型执行；部分工具（如 Codex）还可选择速度档。 |
| **Access** | 决定哪些成员可以运行它。 |
| **执行配置** | 包括并发上限、环境变量、CLI 参数、MCP 和外部集成。 |

更换模型或修改指令不会创建新智能体，过去的任务、评论和执行记录也不会丢失。

## 智能体、运行时和运行

| 概念 | 职责 |
|---|---|
| **智能体** | 决定谁来做、按什么方式做 |
| **运行时** | 决定在哪台电脑、用哪款 AI 编程工具执行 |
| **运行** | 记录这一次执行的过程和结果 |

一个运行时可以承载多个智能体；一个智能体也可以先后完成多次运行。运行时离线时，智能体的身份和历史仍在，但新的运行需要等待运行时恢复。

## 参与工作的方式

- **负责任务**：把智能体设为负责人，运行入队后开始处理。
- **处理一条评论**：在评论中 @智能体，不改变任务的负责人。
- **继续讨论**：回复智能体的评论，新的信息会进入后续执行。
- **直接对话**：开始一段不依附于任务的对话。
- **参与项目和小队**：智能体可以成为项目 lead，也可以担任小队队长或小队成员。
- **通过自动化运行**：按时间表或外部事件触发预设工作，也可以手动运行。

智能体可以创建任务、发表评论和修改工作状态，但它没有收件箱，也不会收到 `@all`。对智能体的 @提及是一次执行触发，不是通知。

## 权限与 Access

每个智能体都有一名 owner 和一个 Access 设置（界面上叫"访问权限"）。Access 决定谁可以运行它，也就是把任务分配给它、在评论中 @它或和它对话：

| Access | 谁可以运行 |
|---|---|
| **仅自己**（Only me） | 只有智能体 owner。 |
| **整个工作区**（Entire workspace） | 工作区中的所有成员。 |
| **指定成员**（Specific people） | 智能体 owner 和指定的成员。 |

| 操作 | 谁可以 |
|---|---|
| 在智能体列表和选择器中看到它 | 智能体 owner、工作区 `owner` 和 `admin`，以及 Access 授权的成员 |
| 修改配置 | 智能体 owner、工作区 `owner` 和 `admin` |
| 修改 Access | 只有智能体 owner |

## 在线、离线和工作状态

智能体列表会同时展示两类状态：

- **可用性**来自运行时，例如在线、离线或不稳定。
- **工作负载**来自运行，例如处理中、排队中或空闲。

"离线"不表示智能体被删除。已经入队的运行会等待运行时恢复；"已归档"才表示它不能再接收新工作。

## 归档和恢复

不再使用的智能体可以归档。归档后，它不再出现在选择器中，也不能被分配或 @提及；历史记录保留，之后可以恢复。

<Callout type="warning">
归档会取消该智能体所有尚未结束的运行，包括排队中和进行中的运行。
</Callout>

智能体 owner 和工作区 `owner`、`admin` 都可以归档或恢复智能体。

## 执行模式对比

智能体的概览页提供默认模式与极简模式对比，可按 UTC 创建日期和 task ID 筛选固定样本。面板显示执行状态成功率、重试、端到端与阶段耗时、各类 Token，以及提供方报告费用和已知价格的估算费用。执行 completed 不代表产物已经通过业务验收。

阶段为环境准备、执行、收尾；执行阶段包含运行时初始化、模型协商、工具调用和消息回传，并非纯模型耗时。旧 task 缺少遥测时显示未知，不补成零。任务级 `concise_mode`、daemon 级 `MULTICA_DIRECT_AGENT_MODE`、模型和发布版本分别记录；配置混杂或缺失时不能据汇总宣称公平对比。

## 飞书话题 PRD

在现有 **Skills** 页面创建工作区技能 `mika-prd` 并绑定到 Mika。PRD 澄清方式、写作规则和草稿展示统一维护在这个可编辑技能中；内置 `multica-prd` 只说明平台命令与安全边界。后续业务调优在网页编辑并保存 `mika-prd`，不必发布新版内置技能，也不要把规则复制到智能体主提示词。修改对新任务生效，不会热更新已经运行的当前轮；保存后请用新任务验证。

在专用话题的首条消息中 @Mika 发起 PRD 需求。工作区技能指导 Mika 读取实时模板，在当前 task 中直接起草，再用 `multica chat prd draft --source-message <根消息ID> --content-file ./prd-draft.json` 保存。Mika 和小码是同一个智能体；保留当前运行时（包括 Hermes），不另配智能体或创建子生成 task。先展示可读草稿，原发起人在同一话题 **@Mika 并发送草稿返回的精确确认语句**后，`publish` 才允许服务端复制模板、填写正文、转移所有权并回传链接。其他成员、机器人、引用消息及旧版本确认不能授权发布。编辑业务技能不能放宽这些校验，也不会改写已确认草稿。

部署需配置模板 `MULTICA_PRD_TEMPLATE_WIKI_TOKEN`。飞书安装需具备模板读取、文档复制与编辑、所有权转移权限；原发起人的绑定身份必须与 task 发起人一致，且仍是工作区成员并有该智能体的调用权限。修改草稿沿用根消息并递增版本，已确认快照不能更改。复制结果不明时停止重建；已知文档失败后继续原文档。确认创建文档不授权自动研发或发布。
