# 设计体系交互约定

- 状态：confirmed（产品交互目标，非实现或验收完成声明）
- 日期：2026-09-08
- 来源：SY-323 产品讨论；以本文件的最新确认覆盖早期交互提案。
- 范围：设计体系入口、生成、浏览、调整与保存；不包含任务评论中的设计交付实现。

## 入口与展示

设计中心首页保留原有 Tab、社区和模板入口。顶部采用 Finder 式“按项目／按仓库”视角切换，Hover 分别提示“项目”“仓库”；新增入口随当前视角选择并打开对象。

仓库视角只使用“设置 → 代码仓库”的仓库，不改变项目原有仓库资源新增方式。打开的项目、仓库内部都去掉“模板”Tab；仅仓库保留“设计体系”，项目不展示该 Tab。

设计体系默认主视图为包内在线 UI Kit。基础、Token、通用组件、页面模式等内部导航由 UI Kit 承载，Multica 外层不重复放置文档式章节导航。

## 生成与实时查看

1. 打开尚无设计体系的仓库时保持未建立状态，不自动启动智能体。用户点击“生成设计体系”后才开始。
2. 按 Open Design 的通用仓库分析与生成链路生成完整设计体系。真实 UI Kit 内容随生成逐步出现在主区域，用户可以边生成边查看；只显示固定百分比、阶段或日志不满足目标。
3. 生成期间可浏览，不提交调整。用户切换到其他项目、仓库或任务页面时生成继续；返回后恢复同一轮的最新进度和已生成内容，不重新启动。这里不承诺关闭执行机器后继续运行。
4. 失败明确展示失败情况和未完成状态。用户重试优先接着本轮已有内容继续生成，不默认从头重跑；失败续接与主动重新生成是不同操作。

## 调整

本轮生成完成后，用户主动进入调整模式，选中 UI Kit 中的组件或区域，再提交针对性的修改要求。

调整面板默认关闭。普通浏览时点击内部导航、按钮和组件，只执行其正常交互，不自动打开调整面板。

第一期不展开组件级修改影响范围等额外交互，不据此引入新的确认流程。

## 草稿与保存

新生成或调整后的内容属于本轮草稿。只有用户明确点击保存，才更新已保存的设计体系；新一轮生成、失败、离开页面或未保存退出，都不能自动覆盖原 saved。

保存后，在首页“我的设计体系”中可以找到并重新打开同一份已保存内容。

## 与设计稿的衔接

设计体系可作为设计稿生成的设计依据，但不是准入条件。没有设计体系时可以引导生成，同时必须允许用户直接创建设计稿，不强制跳转、不禁用提交，也不在后台替用户启动设计体系生成。两种路径都遵循 Open Design 的设计稿生成链路。

## 交互检查清单

- 打开仓库不执行，点击生成才执行。
- 主区域逐步出现真实 UI Kit；应用内切换并返回后仍为同一轮任务。
- 生成中只浏览，完成后主动选择组件或区域调整；普通点击不弹抽屉。
- 失败重试优先续接有效产物，不冒充成功或偷偷从头生成。
- 未明确保存时旧 saved 保持不变；保存后首页可找回。
- 不指定设计体系也可以正常创建设计稿。

主路径：打开仓库 → 手动生成 → 实时查看 UI Kit → 完成后按需调整 → 明确保存 → 首页再次打开。
